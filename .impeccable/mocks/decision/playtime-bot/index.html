4

The Conquest post

When a Game Completion makes a member Conquer a Franchise (a Game Completion for every Mainline game), the bot says so in the completions channel. No pings. Conquests that already exist when the Feature launches, and ones reached through a Completionator import, are never posted. Gated by the Franchise Progress Feature.

4A

A line on the completion post

No new message: the Game Completion that finishes the last Mainline game gets one more line on its usual post in the completions channel. The member's name is plain text, never a ping.

  • Quietest; it can't be missed because it rides the post people already read.
  • A Conquest from a Game Completion logged without announce:true posts nothing. Say if it should post on its own then.
4B

Its own card under the completion

Right after the completion post, a Conquest card: the headline, the date, a gallery of the Franchise's Mainline covers, the Playtime and who else has Conquered it, and a link to the Franchise page. Recommended: it reads as an event of its own without a new channel.

  • The gallery holds 10 covers, so a long Franchise shows its latest 10 Mainline games with art.
  • The container's 3px edge is paper, not a Provider or track colour.
4C

The printed Conquest

The card is a generated image in the club's print style: the full Mainline meter with the Conquered stamp, all 16 Mainline covers numbered I to XVI (the Anton fallback where IGDB has none) and the Playtime, with one line of text under it.

  • Most like the website; needs the bot to render an image (it already draws birthday banners), so it costs the most to build.
  • Fits every Mainline game, where the gallery stops at 10.
5

/playtime add

/playtime add title platform hours [set] adds to (or with set:true, sets) the member's Manual Playtime for one game on one platform. Replies are ephemeral. Not gated: Playtime is part of every game page.

5A

One line and Undo

An ephemeral line that says what changed (from and to) and the new Playtime, with Undo. set:true says "Set" and shows what it was.

  • Fastest to read; nothing about other sources or the Playthrough.
5B

The receipt

The reply is a receipt: the game's cover, the new total, every source with the changed one marked, the open Playthrough, and the mismatch as one plain line pointing to the website. Recommended: adding time is when members check whether the total is right.

  • The Playthrough grew by the 3 h too, because Manual time added while a Playthrough is open counts toward it.
5C

Ask first when a Provider covers it

Same reply as 5A, but when the platform is one a Provider already reports for this game, the bot asks before adding: "Steam already reports 42 h on PC", with Add anyway or Cancel. Catches the double count at the source.

  • Can combine with 5A or 5B for the normal reply.
  • The red Add anyway is Discord's danger style; on the website the same warning is the yellow mismatch.
6

Playtime in the game view

The bot's existing game view (/gamedb view) and its buttons. Today it shows the game, Time to beat and the shelf buttons.

6A

A block in the view

The game view gains a Playtime block for whoever ran the command, named so everyone reading knows whose it is: the total, the sources on one line and the open Playthrough.

  • Simple, but a game view posted in a channel shows only its author's Playtime.
6B

My Playtime, for whoever presses it

The view gets a My Playtime button. Whoever presses it gets their own breakdown, ephemeral: a small table of sources, the total and the open Playthrough. Recommended: one posted view works for every member reading it.

  • The table is a code block so the hours line up; it stays under 2,000 characters for any game.
6C

The club's Playtime, yours on the button

The view shows the club's Playtime on the game (total, members, the top three) and a line on its Franchise, with 6B's My Playtime button for your own.

  • Needs a club Playtime figure from the API, which the spec doesn't have yet.
