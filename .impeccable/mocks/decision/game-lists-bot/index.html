Game Lists in Discord

Options for every message the bot sends for Core and Optional Games, Pool Proposals and Game Lists (spec api#442, ticket www#168). Pick one per surface, or mix parts of several. Every mock uses only what the bot can really send: plain content or Components V2 (containers, sections, text, separators, thumbnails, media galleries, buttons, selects), modals and autocomplete. Each frame lists its component and character budget. The website's options are in ../game-lists/.

1

/challenge Pool wizard

Creating or editing a Pool now means choosing the Core Games every Run must Clear, the Optional Games the sources bring, and how many Optional Games a Run also Clears (0 by default). A Host can start from one of their Game Lists; its games come in as Core. Sources are a Franchise or a Series, and the word Collection goes away. Each option shows the Fall of Final Fantasy preview, a select or modal open, the Soulslike Challenge started from Grindlord's list, and the Run line on /challenge view.

1A

Two lines, one tick-box

The wizard you have today, kept to its two steps. The preview names the Core Games and where the Optional Games come from in two lines, and one select decides Core: ticked is Core, unticked drops to Optional. The target is a button that opens a one-field modal.

  • Smallest change to ChallengeWizard.ts: the existing preview grows a Core select and a target button.
  • Moving a game is one untick or tick. There's no separate Optional list to manage: Optional is whatever the sources bring plus the unticked ones.
  • A Franchise's Mainline games arrive pre-ticked as Core (spec story 41); a Series brings everything as Optional.
  • 26 games need two pages of 25 in the select, so paging buttons appear, as for Leave games out today.
1B

One question a step

The wizard grows to four steps: basics, sources, Core Games, then Optional Games and the target. Each step lists its games by name and moves them with a Make Optional or Make Core select. The target is a - 2 + stepper of buttons, so there's no modal.

  • Clearest for a first-time Host: each step answers one question, and the words match the website's two columns.
  • Two more steps to click through, and the cover preview moves to the end (the Preview button) rather than every step.
  • The view's bars are block characters in text, not an image, so they read in any client and in screen readers as numbers.
1C

The Pool shelf

A generated image in the club's print style shows the Pool as two shelves, Core over Optional, with every cover. Under it, three lines (Core, Optional, the target) each carry their own Edit button. The same image comes back on /challenge view with your Cleared games ringed.

  • The only option where a member sees all 26 games at once, including the ones without art (they get the Anton title fallback, as on the website).
  • Needs a new image composer, like ChallengeShelfImage. The media gallery today stops at 10 covers.
  • Edit Core works one game at a time (pick, then Keep / Move / Leave out), which is slower for big moves but can't go wrong.
2

Pool Proposals and DMs

Any member can propose a game for a Pool Challenge. A game already in the Pool or already pending is refused; a left-out game can be proposed. The Host (or any Moderator for a club-hosted Challenge) accepts it as Core or Optional, or declines it, and is asked whether to add it to a linked list. Three DMs go out, all respecting the Challenge DM opt-out: pool_proposal to the Host, pool_proposal_accepted to the proposer, and pool_goal_changed to members with a Run when a save adds Core Games or raises the target. Club-hosted proposals post in #dev instead of DMing.

2A

A row per proposal

The Host's inbox lists every pending Pool Proposal as a line with its own three buttons. DMs are one sentence and a button, in the voice of today's Challenge DMs.

  • Deciding is one click per proposal, with no extra step.
  • Each proposal costs 6 components (separator, text, row of 3), so a page holds 5. Busy Challenges page with Previous and Next.
  • The pool_goal_changed DM lists each change on its own line, one DM per save, and ends with the opt-out.
2B

One proposal at a time

Each Pool Proposal gets the whole card: its cover, who proposed it, what Core and Optional mean for the Run, and a note when the game was left out. The Host steps through them. DMs carry the game's cover too.

  • The Host sees what accepting as Core costs members before they click it.
  • Slower when ten proposals pile up: one card each.
  • The #dev post links to the Challenge rather than deciding in place, so staff decide where they can see the whole Pool.
2C

Triage in one select

The inbox is a single tick-box select of every pending Pool Proposal (up to 25), and the buttons act on all the ticked ones at once. DMs shrink to one line each with the Challenge's name first, so a DM list scans like a feed.

  • Fastest for a busy Host or the club's staff: clear ten proposals in two clicks.
  • The buttons' labels count the ticked ones, so the Host knows what will happen.
  • Easy to accept a game as Core by accident in a batch; the Core DMs to members would then go out. A confirm step for Core could guard it.
3

/list view and Add to list

Members can read any Game List they can see with /list view, and add a game to one of their own with /list add or an Add to List button on the game view. Reordering and notes stay on the website, so every reply points there. Both are gated by the Game Lists Feature. A game appears in a list once, and a list holds up to 500.

3A

The list as text

/list view is the list as a numbered page of text, with each game's note in small type under it and the first game's cover as the thumbnail. On the game view, Add to List fills the fifth and last slot of the existing button row and opens a select of your lists.

  • Cheapest to build and fully readable without images. 10 games and their notes fit one page; 500 games page in tens.
  • The row now holds exactly 5 buttons, Discord's limit, so a future game action needs a second row.
  • Lists that already have the game say so in the select (Discord can't disable an option); picking one gets the refusal.
3B

Covers on the shelf

/list view leads with the list's covers as a media gallery (10 to a page), then a compact numbered list of titles. Notes open on Show notes for whoever asks. Add to List opens a small modal with a select of your lists and adds the game at the end.

  • Most visual, and closest to the website's list page. Games without art are left out of the gallery but stay in the numbered lines.
  • The gallery's cover grid crops to Discord's layout; at 10 covers it's 5 across.
  • A modal with a select needs discord.js's newer Label component (modal selects). If the bot's version lacks it, the select moves to an ephemeral reply as in 3A.
3C

A card per game

/list view gives each game a section of its own: rank and title, year, the note, and the cover beside it, five to a page. The game view gets a second button row for lists: Add to a Game List and In 6 Game Lists, which shows the lists the game is in.

  • Reads like the website's list page, notes and all. A ranked list of 500 pages 100 times, so Open on the website matters more.
  • Each game costs 3 components (section, text, thumbnail), so 5 per page keeps well under 40.
  • In 6 Game Lists needs the count and the visible lists from GET /games/:id/game_lists, which the API already plans.
